# POV Shift Detector — Architecture Specification

## 1. Architecture Overview

The system is implemented as a modular processing pipeline.

The public component is `POVShiftDetector`, which orchestrates the detection process. Each processing stage has a specific responsibility and communicates with the next stage through structured domain objects.

Conceptual pipeline:

```text
Input Text
    ↓
analyze()
    ↓
resolve_coreference()
    ↓
detect_internal_states()
    ↓
update_focus()
    ↓
detect_shift()
    ↓
POVShift[]
```

The architecture must preserve the distinction established by the specification:

```text
Clauses
    ↓
linguistic analysis and evidence

Sentences
    ↓
unit across which narrative focus is evaluated

FocusState
    ↓
narrative focus

POVShift
    ↓
detected focus change
```

The detector must not place all linguistic and narrative logic inside a single method.

---

## 2. Main Component: `POVShiftDetector`

`POVShiftDetector` is the main public application/service component.

It exposes the public detection interface:

```python
def detect(self, text: str) -> list[POVShift]:
    ...
```

The caller provides raw English text.

The caller should not need to know about:

* spaCy;
* clause extraction;
* coreference resolution;
* internal-state detection;
* narrative focus tracking;
* POV shift classification.

`POVShiftDetector` coordinates these processing stages but does not contain all of their internal logic.

---

## 3. Main Pipeline

The complete processing pipeline is:

```text
Input text
    ↓
analyze()
    ↓
resolve_coreference()
    ↓
detect_internal_states()
    ↓
update_focus()
    ↓
detect_shift()
    ↓
return POVShift[]
```

The conceptual data flow is:

```text
str
 ↓
Clause[]
 ↓
Clause[] with resolved references
 ↓
Clause[] with internal-state evidence
 ↓
FocusState[]
 ↓
POVShift[]
```

Each stage consumes the structured information produced by the previous stage.

---

## 4. `detect()`

**Objective:** Orchestrate the complete POV shift detection process.

`detect()` is the main entry point and coordinates the processing stages without implementing their internal linguistic logic.

**Signature:**

```python
def detect(self, text: str) -> list[POVShift]:
    ...
```

**Preconditions:**

* `text` is not `None`;
* `text` is a non-empty `str`;
* required NLP components are initialized.

**Postconditions:**

* returns `list[POVShift]`;
* the list may be empty when no POV shifts are detected.

**Conceptual flow:**

```python
clauses = analyze(text)
clauses = resolve_coreference(clauses)
clauses = detect_internal_states(clauses)
focus_history = update_focus(clauses)
shifts = detect_shift(focus_history)
return shifts
```

`detect()` coordinates the stages but does not replace their specialized responsibilities.

---

## 5. `analyze()`

**Objective:** Convert raw English text into structured linguistic information using spaCy.

**Signature:**

```python
def analyze(self, text: str) -> list[Clause]:
    ...
```

**Preconditions:**

* `text` is a valid non-empty string;
* a spaCy English model is available.

**Postconditions:**

* returns an ordered list of `Clause` objects;
* clauses preserve their original textual order;
* each clause contains the linguistic information available according to `FR-01` and the domain model;
* each clause is associated with its sentence through `sentence_index`.

**Responsibilities:**

* tokenization;
* sentence segmentation;
* clause extraction;
* lemma extraction;
* part-of-speech tagging;
* dependency analysis;
* subject identification;
* verb identification;
* entity recognition.

`analyze()` provides linguistic information only.

It must not:

* resolve ambiguous coreference;
* determine narrative focus;
* classify a POV shift.

**Important restriction:**

A change of subject or character detected during linguistic analysis must not automatically be classified as a POV shift.

---

## 6. `resolve_coreference()`

**Objective:** Determine which textual mentions refer to the same narrative entity.

**Signature:**

```python
def resolve_coreference(self, clauses: list[Clause]) -> list[Clause]:
    ...
```

**Preconditions:**

* `clauses` were generated by `analyze()`;
* clauses preserve their original order.

**Postconditions:**

* resolvable mentions are associated with `Character` objects;
* mentions referring to the same entity use the same `Character`;
* ambiguous references are represented as unresolved or ambiguous rather than arbitrarily resolved.

**Example:**

```text
John entered the room.
He sat down.
```

Result:

```text
He → Character(John)
```

The same `Character` identity is therefore available to later stages.

For:

```text
John met Paul.
He smiled.
```

the resolver must not arbitrarily choose:

```text
He → John
```

or:

```text
He → Paul
```

when the reference cannot be resolved reliably.

**Important restriction:**

Coreference resolution must occur before narrative focus comparison.

---

## 7. `detect_internal_states()`

**Objective:** Identify clauses that provide evidence of internal experience.

**Signature:**

```python
def detect_internal_states(
    self,
    clauses: list[Clause]
) -> list[Clause]:
    ...
```

**Preconditions:**

* clauses contain linguistic information produced by `analyze()`;
* verb lemmas are available when possible.

**Postconditions:**

Relevant clauses have the following information populated when determinable:

```text
internal_state
state_type
experiencer
```

Possible `state_type` values are:

```text
cognition
emotion
perception
None
```

**Example:**

```text
John wondered where Mary was.
```

Result:

```text
internal_state = True
state_type = cognition
experiencer = John
```

This stage identifies evidence of internal experience.

It does not determine whether a POV shift occurred.

In particular:

```text
internal state
    ≠
POV shift
```

---

## 8. `update_focus()`

**Objective:** Maintain the narrative focus in textual order.

**Signature:**

```python
def update_focus(self, clauses: list[Clause]) -> list[FocusState]:
    ...
```

**Preconditions:**

* clauses are ordered;
* coreference resolution has been performed;
* internal-state detection has been performed;
* each clause retains its `sentence_index`.

**Postconditions:**

* returns an ordered list of `FocusState` objects;
* focus is evaluated according to sentence order;
* focus establishment, maintenance, and change are distinguished;
* focus is updated only when sufficient evidence exists.

### Sentence-level focus evaluation

Although `update_focus()` receives `Clause` objects, clauses are not treated as independent POV decision units.

Clauses provide evidence for the focus associated with their containing sentence.

For example:

```text
John opened the door and Mary felt afraid.
```

contains:

```text
Sentence 0
    Clause 0 → John
    Clause 1 → Mary
```

Both clauses have:

```text
sentence_index = 0
```

Therefore, the change from John to Mary must not automatically create a sequence such as:

```text
John → Mary
```

for POV shift purposes.

The focus evaluation remains associated with the sentence.

### Example

Input:

```text
John wondered where Mary was.
He felt nervous.
Mary knew he was waiting.
```

After coreference:

```text
He → John
```

The focus history may be:

```text
Sentence 0 → John
Sentence 1 → John
Sentence 2 → Mary
```

This produces the conceptual focus sequence:

```text
John → John → Mary
```

`update_focus()` maintains this narrative state but does not decide whether the final change constitutes a POV shift.

---

## 9. `detect_shift()`

**Objective:** Determine whether changes in narrative focus constitute POV shifts.

**Signature:**

```python
def detect_shift(
    self,
    focus_history: list[FocusState]
) -> list[POVShift]:
    ...
```

**Preconditions:**

* `focus_history` was generated by `update_focus()`;
* focus states are ordered by sentence.

**Postconditions:**

* returns `list[POVShift]`;
* each detected shift contains:

  * previous focus;
  * new focus;
  * sentence location;
  * confidence;
  * supporting evidence.

### Conceptual evaluation

`detect_shift()` evaluates changes between established narrative focus states associated with different sentences.

The detector must preserve the distinction between:

* focus establishment;
* focus maintenance;
* focus change.

A focus change is evaluated against the previously established narrative focus, not against an absence of focus.

For example:

```text
John
None
Mary
```

represents:

```text
John = previously established focus
None = no new focus established
Mary = new focus
```

The relevant comparison is therefore:

```text
John → Mary
```

A missing or unresolved focus must not be treated as a new character or as evidence of a POV shift.

For a sequence such as:

```text
John
John
Mary
```

the relevant comparisons are:

```text
John → John
John → Mary
```

Only the second comparison represents a focus change.

The classification must remain consistent with the detection rules.

In particular, the following must not independently produce a POV shift:

```text
subject change
character change
grammatical person change
pronoun change
```

A POV shift requires evidence that narrative focus moved from one character's internal experience to another character's internal experience across sentence boundaries.

The result must contain the evidence actually used by the detector.

## 10. Domain Model Interaction

The architecture uses the domain objects:

```text
Character
Clause
FocusState
POVShift
```

### `Clause → Character`

A clause may reference a `Character` through:

```text
subject
experiencer
```

when these can be reliably determined.

### `Clause → FocusState`

Clauses provide linguistic evidence used to establish or maintain the narrative focus associated with their sentence.

### `FocusState → POVShift`

Focus states are compared to determine whether a focus change constitutes a POV shift.

Conceptually:

```text
Clause
    ↓
subject / experiencer
    ↓
Character
    ↓
FocusState
    ↓
focus comparison
    ↓
POVShift
```

The architecture does not introduce a separate `Sentence` domain class.

Sentence membership is represented through the `sentence_index` associated with the relevant domain objects.

## 11. Responsibility Separation

Each processing component should have a single primary responsibility.

```text
NLPParser
    ↓
linguistic analysis

CoreferenceResolver
    ↓
entity/reference resolution

InternalStateDetector
    ↓
internal-state evidence

NarrativeFocusTracker
    ↓
focus state

ShiftDetector
    ↓
POV shift classification

POVShiftDetector
    ↓
pipeline orchestration
```

The components should communicate through the domain model rather than exposing implementation-specific details unnecessarily.

---

## 12. Dependency Direction

The preferred dependency direction is:

```text
POVShiftDetector
        ↓
processing components
        ↓
domain model
```

The domain model must not depend on spaCy.

For example:

```text
Character
```

must not know that spaCy exists.

Likewise:

```text
Clause
```

must represent domain-level linguistic information rather than directly exposing a spaCy `Doc`, `Token`, or other spaCy-specific object.

This keeps the domain model independent from the NLP implementation.

---

## 13. Recommended Internal Components

The implementation may separate the pipeline into specialized components:

### `NLPParser`

Responsible for:

* spaCy processing;
* linguistic analysis;
* clause extraction.

### `CoreferenceResolver`

Responsible for:

* associating textual mentions with `Character`;
* identifying unresolved or ambiguous references.

### `InternalStateDetector`

Responsible for:

* detecting internal-state evidence;
* classifying it as:

  * cognition;
  * emotion;
  * perception;
* identifying the experiencer when reliably determinable.

### `NarrativeFocusTracker`

Responsible for:

* maintaining narrative focus in textual order;
* distinguishing focus establishment, maintenance, and change;
* producing `FocusState` objects.

### `ShiftDetector`

Responsible for:

* comparing narrative focus states;
* applying the detection rules;
* producing `POVShift` objects;
* calculating confidence and evidence according to the defined rules.

### `POVShiftDetector`

Responsible for:

* exposing the public `detect()` interface;
* orchestrating the processing components;
* returning the final `POVShift[]`.

The component names describe implementation responsibilities. They do not introduce additional functional requirements.

## 15. Architectural Principle

The core architectural principle is:

```text
Raw Text
    ↓
Linguistic Structure
    ↓
Entity Resolution
    ↓
Internal Experience
    ↓
Narrative Focus
    ↓
Focus Comparison
    ↓
POV Shift
```

The architecture must not jump directly from:

```text
subject change
```

to:

```text
POV shift
```

Instead, the inference must be supported by the intermediate representations defined by the domain model.

The distinction between linguistic analysis and POV decision must be preserved:

```text
Clause
    ↓
linguistic evidence

Sentence
    ↓
focus comparison unit

FocusState
    ↓
narrative state

POVShift
    ↓
final detection result
```

---

## 16. Rationale

The modular architecture makes the detector easier to:

* test;
* explain;
* debug;
* maintain;
* extend.

Each processing stage can be tested independently while the integration layer verifies the complete pipeline.

The separation also allows individual implementation strategies to change without requiring changes to the domain model.

For example, the coreference implementation may change while the domain concepts remain:

```text
Character
Clause
FocusState
POVShift
```

The same principle applies to the NLP parser and internal-state detection components.

The architecture therefore provides the implementation structure required to preserve the requirements and detection rules without embedding the entire detection algorithm into a single component.
